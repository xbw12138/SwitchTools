# SwLink 使用教程（从零到串流）

一句话:把 Switch(装了大气层)的系统模块放到 SD 卡上,Mac 上跑一个客户端,插一根 USB 线就能
看到 Switch 画面和声音,还能直接管理 SD 卡文件。不用采集卡,不用网络。

```
Switch ──USB-C──> macOS
  ├─ 画面 + 声音(H.264 720p30 + PCM 48kHz 立体声)
  └─ SD 卡文件浏览 / 上传 / 下载 / 删除 / 重命名
```

---

## 1. 准备清单

| 项目 | 要求 |
| --- | --- |
| Switch | 已装**大气层(Atmosphere)**,已验证 1.7.x + 系统 18.1.0 |
| Mac | macOS 12 及以上(已验证 12.7.6 Intel);Apple 芯片同样可用 |
| 数据线 | **能传数据的 USB 线**(很多充电线没有数据线芯,这是"找不到设备"的头号原因) |
| SD 卡读卡器 | 装机时用一次,之后不再需要 |

> ⚠️ 同一台 Switch 上**不要同时安装 SysDVR 和 SwLink**:两者都独占 `usb:ds`,会互相抢设备。

---

## 2. 装 Switch 端(约 2 分钟)

**先关机再拔 SD 卡**(热拔卡容易损坏文件)。把 SD 卡插到 Mac,然后放这 3 个文件:

```
SD:/atmosphere/contents/00FF0000A53B5A57/
├── exefs.nsp            ← 发布包里的 swlink.nsp,改名成 exefs.nsp
├── toolbox.json         ← 直接复制,内容不用改
└── flags/
    └── boot2.flag       ← 空文件(0 字节),有这个文件才会开机自启
```

> 目录名 `00FF0000A53B5A57` 是 SwLink 的 title id,**必须一字不差**。新建 `flags` 文件夹时注意
> 不要在名字里带空格。

放好后弹出 SD 卡、插回 Switch、**开机**。

### 2.1 30 秒确认:sysmodule 到底起来没有

开机进入系统后,把 SD 卡拔回 Mac 看**根目录**:

- ✅ 出现 `SwLink.log`,里面有下面几行 → 系统模块已启动,可以继续
  ```
  == __appInit 完成 ==
  ======== SwLink 启动 ========
  captureInitialize: 0x00000000
  usb init: 0x00000000
  USB 已使能, 等待主机连接
  ```
- ❌ **没有 `SwLink.log`** → 模块没被加载,不要继续折腾 Mac 端,直接看第 5 节。

（`SwLink.log` 每次开机会追加一段,只认最后一段即可。）

---

## 3. 装 Mac 端

```sh
cd mac
./setup.sh            # 装 brew 依赖 + 自行编译精简版 ffmpeg(只要 h264 解码)
open build/SwLink.app # 双击 App 启动客户端(无需命令行)
```

- 依赖:`cmake`、`sdl2`、`libusb`、`pkg-config`;ffmpeg 由脚本自动下载编译到
  `mac/third_party/ffmpeg`,不入库,也不需要 Homebrew 的 ffmpeg。
- 构建产物 `build/SwLink.app` 已把依赖库和图标打进包内并做了本地签名,可以单独拷给别人用;
  若首次打开被系统拦截,右键 → 打开。
- 之后改了代码只需要 `cmake --build build -j`(会自动重新打包 App)。
- Mac 上**不需要装任何 USB 驱动**,客户端会自动 detach 系统占用。

---

## 4. 使用

1. Switch 开机,USB 线连接 Mac(接 Switch 底部 USB-C 口)。
2. 打开 `SwLink`,在「串流画面」页点右上角 **连接 Switch**。
3. **进入一个游戏才有画面**——主菜单、设置、相册这类系统界面不产生录制输出,停留在
   主菜单会一直显示「等待画面...」。这是 Switch 系统录制接口的限制,不是 SwLink 的问题。
4. 串流页工具栏三个按钮:
   - **独立窗口**:弹出一个只有画面的窗口(默认 1280×720,可缩放、可拖到副屏/外接屏),
     按 16:9 居中铺满;打开后主窗口画面区会变成提示文字(不再重复渲染),点「关闭窗口」
     或关闭独立窗口即回到主窗口显示。
   - **全屏**:把整个主窗口(带界面)全屏;想要纯画面满屏,用「独立窗口」再点 macOS 绿色按钮。
   - **静音/取消静音**:只影响 Mac 本机播放,不影响主机。
5. 「SD 卡文件」页可以浏览 SD 卡根目录,双击进入文件夹;支持多选(Cmd/Shift)下载、
   点表头排序、递归下载整个文件夹、上传、新建目录、重命名、批量删除;把本地文件**或文件夹**
   拖进窗口也会直接上传到当前目录。传输中显示速度与剩余时间,可随时「取消」。
   页面底部会显示 SD 卡剩余空间(需设备端为新固件,见第 2 节)。

连接成功的标志:「已连接,串流中」+「已解码帧」数字不断增长。

## 5. 常见问题速查(按现象找)

| 现象 | 真正的原因 | 处理 |
| --- | --- | --- |
| 提示「未找到设备 16C0:27DA」 | 模块没启动 / 线是充电线 / 被别的程序占用 | 先看 SD 卡有没有 `SwLink.log`;换一根确定能传数据的线;关掉 DBI 的 MTP 模式;确认没装 SysDVR |
| 有 `SwLink.log` 但 Tesla 里显示「未启用」 | Tesla 界面版本太老,读不到新模块 | 不影响使用,以 `SwLink.log` 为准 |
| 一直「等待画面...」 | 停在主菜单,或该游戏禁止录制 | 进游戏并停留在游戏画面 10 秒以上 |
| 连上后自己变回「连接已断开」 | USB 读超时/线接触不良 | 重新插拔线,再点一次连接 |
| 声音有延迟或断续 | 音频批量块数偏大 | 属正常范围;延迟主要来自系统录制接口本身 |
| 画面糊/锯齿 | 窗口尺寸与 720p 不成比例 | 已启用线性缩放;把窗口拉到接近 16:9 更清晰 |
| 文件页签打不开 SD 卡 | 模块未启动 | 同第一行 |
| 界面个别字显示成方块/乱码 | 字体缺字形(常见于「屏」这类字) | 客户端已内置补字表;自编译时确认 `System/Library/Fonts/PingFang.ttc` 存在 |
| 独立窗口画面只占左上角一小块 | 旧版客户端在 Retina 屏上算错了画布尺寸 | 用最新 `build/SwLink.app`;已改为按渲染器输出尺寸铺满 |
| 文件页底部不显示 SD 剩余空间 | 设备端还是旧版 nsp(缺 `StatFs` 命令) | 重新部署 `exefs.nsp` 并关机重开(旧固件只是不显示容量,其它功能正常) |
| 双击 App 提示「无法打开,因为无法验证开发者」 | 本地临时签名,未经 Apple 公证 | 右键 App → 打开,或「系统设置 → 隐私与安全性 → 仍要打开」 |
| 开机后黑屏/进不去系统 | 模块与固件不匹配 | 关机拔卡,删掉 `atmosphere/contents/00FF0000A53B5A57` 整个文件夹即可恢复 |

## 6. 开发者注意:最大的坑是 libnx 版本

自己从源码编 sysmodule 时:**libnx 必须用与主机固件同期的版本**。

- ❌ 用 devkitPro 最新 libnx(2026 master)编出来的 sysmodule,在 18.1.0 上会**静默不加载**:
  没有日志、没有崩溃报告、Tesla 里显示「未启用」,极难定位。
- ✅ 换成与 18.1.0 同期的 **libnx v4.12.0** 重新编译,立刻正常。

```sh
# 降级 libnx 后重编
cd /path/to/libnx && git checkout v4.12.0 && make -j8 && sudo make install
cd switch && make clean && make -j4
```

另外几处容易踩的点(完整排查过程见 [sysmodule-not-loading.md](sysmodule-not-loading.md)):

- `exefs.nsp` 是 **PFS0 包**(`main.npdm` + `main`),不是 nro;sysmodule 不能当游戏安装。
- 必须有 `flags/boot2.flag` 才会开机自启。
- 主线程栈、堆大小照 SysDVR 的写法即可(本仓库 `swlink.json` 已配好),不要照抄网上的 4KB 栈。
- 编译缺 `bin2s` 时,可自写一个生成 `.incbin` 汇编的小脚本放到 PATH。

## 7. 画质与流畅度能改多少

- 画面由 Switch 系统的 `grc:d` 录制接口输出,**固定 720p / 30fps / H.264**,比特率不可调。
  所以"清晰度"的天花板就在这里,和官方串流一样。
- SwLink 已做的优化:
  - Mac 端用大缓冲一次性读 USB 包(小缓冲会丢掉包内剩余数据,表现为卡顿/花屏)
  - 线性纹理缩放(消除缩放锯齿)
  - H.264 切片多线程解码
  - 偶发 USB 写超时只丢单帧并要求下个关键帧带 SPS/PPS,不再整段断开
- 想要更高画质只能改系统层录制参数(需要逆向 `grc:d`),本工具不提供。

## 8. 目录结构

```
switch/             Switch 端 sysmodule(C,devkitPro + libnx)
  source/           main / capture(视频音频采集) / stream_server(握手发送) / usb_link / file_server
  swlink.json       NPDM 配置(title id、栈大小、服务访问)
  Makefile
mac/                macOS 客户端(C++17,SDL2 + ImGui + FFmpeg + libusb)
  src/              main(UI) / usb_link / stream_client / video_decoder / audio_output / file_client
  macos/            Info.plist 与 AppIcon.icns
  scripts/          bundle_app.sh(打完可双击的 .app,内置依赖库)
  setup.sh          依赖安装 + 精简 ffmpeg 编译
protocol/           两端共享的通信协议定义 swlink_protocol.h
docs/               本教程 + 排错笔记
```

协议要点:USB VID:PID `16C0:27DA`,两个 vendor 接口(0=串流,1=文件);串流包 = 18 字节头
(magic + 大小 + 时间戳 + 类型 + 标志)+ 负载。

## 9. 想复用到别的设备?先看清边界

这套方案是"协议 + 主机客户端 + 设备端实现"三层,只有前两层是跨平台通用的。

**可以直接复用的部分**

| 层 | 复用度 | 说明 |
| --- | --- | --- |
| `protocol/swlink_protocol.h` | 100% | 包格式、文件命令语义(9 条)都不依赖 Switch |
| Mac 客户端(UI/解码/文件传输) | 约 80% | 只要目标设备按协议发包,客户端几乎不用改;仅 `usb_link.cpp` 绑定 USB |
| 设备端代码 | 约 10% | 采集、USB 设备模式、文件系统全是 Switch 专属 API |

**移植时要替换的三件事**

1. **画面来源 + 编码**:Switch 用 `grc:d`(系统录制,固定 720p30 H.264)。别的设备要各自实现:
   - Android:`MediaProjection` 采集 + `MediaCodec` 硬编 H.264
   - Windows/macOS/Linux PC:Desktop Duplication / ScreenCaptureKit / X11 抓屏 + NVENC/x264
   - 开发板(树莓派等):DRM/KMS 或 V4L2 采集 + `v4l2-m2m`/x264
2. **传输通道**:目前是 USB 设备模式(`usb:ds` → libusb)。若目标设备没有 USB gadget,
   换成 TCP/UDP 即可——协议层不变,只需另写一个 `Transport` 实现。
3. **文件系统访问**:把 9 条命令(列出/查询/读/写/新建目录/删除/重命名/容量/PING)映射到
   目标系统的文件 API 即可,注意路径统一用 `/` 开头、按 512KB 分块。

**推荐的改造顺序**

1. 把 `mac/src/usb_link.{hpp,cpp}` 抽成 `Transport` 接口(`write` / `readSome` / 超时),
   `stream_client`、`file_client` 只依赖该接口;
2. 设备端保留"Annex-B H.264 帧 + 18 字节包头"的封装逻辑,只替换采集与发送实现;
3. 先用 TCP 打通,再按需换成 USB/Wi-Fi 直连;
4. 带宽参考:720p30 H.264 约 5–8 Mbps,USB 2.0/局域网都够用;延迟主要来自编码与缓冲,
   建议端到端保持 <2 帧缓冲。

**不改协议就能换端的前提**:设备端输出的视频必须是 Annex-B(H.264 带 SPS/PPS)、
文件接口按 `swlink_protocol.h` 的请求/响应头布局(40 字节头 + payload)实现。
满足这两点,Mac 客户端可以直接拿来用。
